# Baseline 2026-11-22 — speed + memory (real in-app numbers)

Second baseline from the harness (`dragent/scripts/bench/`), superseding the
headless-proxy tables below. Cold start, input latency, frame times and the
memory scenario are measured in the REAL dev app: a dev-terminal window
(single local terminal) driven over the automation server, with a scratch
`DRAGENT_DEV_HOME` created and deleted per run. Binaries were built with
`--features performance-harness` (automation `run` only registers a local
terminal session in such builds). Both columns used the same driver and the
same load; the baseline column is the original t2 code at `9ed52d3b` plus
only the frame-hook commit, the branch column is this branch.

Unsigned dev CLI answers `signed_out` for `workspaces`/`panes`, and signing
into a dev build is forbidden — so N agents stream as background jobs in ONE
real app terminal (same PTY, grid, frames, pty memory; tabs stay at 1), and
tab switch + workspace creation stay labelled proxies (the automation server
has no tab-switch command). The code-index/host services spawn lazily, so
their rows vary run to run (see scenario notes).

Shared machine (other workers building at times); free memory stayed above
2.8 GB the whole time — above the 1.5 GB guard, no early stop. Memory metric:
macOS `phys_footprint` via one batched `footprint -f bytes` call per sample
(`ps` RSS fallback); agents' rows are exact-PID footprints.

## In-app measures (`dragent/docs/perf/data/measures.csv`, `[branch]` /
`[baseline t2+hook]` notes)

| measure | baseline (t2 + hook) | this branch | method |
|---|---|---|---|
| cold start (launch → first presented frame) | 731 ms (runs 555/731/813) | 740 ms (runs 703/740/915) | in-app-first-frame (dev-terminal window; wall ~1.0 s both) |
| input latency (key → frame, n=60) | p50 5.9 ms, p95 13.6 ms | p50 4.9 ms, p95 14.0 ms | in-app-log (`bench.input key_to_frame_ms`) |
| frame intervals while 10 agents stream | median p50 212 ms, p95 max 1681 ms, max 1681 ms (92 one-second aggregates) | median p50 253 ms, p95 max 845 ms, max 845 ms (95 aggregates) | in-app-frames (`bench.frame` gaps between presented frames) |
| frame render cost over the same stream | 487 frames presented, cumulative render avg 11.4 ms/frame, max 873 ms | 506 frames presented, cumulative render avg 2.0 ms/frame, max 97 ms | automation `perf_stats` deltas (render duration, not interval) |
| tab switch | stayed proxy | stayed proxy | unsigned CLI cannot reach panes; no automation tab-switch |
| worktree/workspace creation | stayed proxy | stayed proxy | `workspaces create` needs sign-in |

Frame-interval vs render: under the 10-agent burst load the app presents
~5–7 frames/s (median inter-frame gap ~200–250 ms either branch) while each
render costs ~2–11 ms on average — presentation coalesces under PTY flood;
the worst single renders (up to ~873 ms) are the multi-thousand-line bursts.
Single runs each; burst timing dominates, so treat small gaps as noise.

## Scenario (`gui-scenario-mem.csv` branch, `gui-scenario-mem-baseline.csv`)

12 fake agents in 1 real app terminal (multiplexed; see above), sampled every
second, then 9 of 12 stopped while sampling 30 s more.

| role | baseline peak / mean MB | branch peak / mean MB |
|---|---|---|
| gui (dev app itself) | 208.6 / 187.0 (n=148) | 195.2 / 189.0 (n=171) |
| host service | no rows (never spawned in window) | 8.5 / 8.3 |
| code-index service | no rows (never spawned in window) | 7.2 / 7.2 |
| agents (summed) | 298.7 / 221.8 | 269.8 / 201.1 |

No `pty` row: the dev-terminal window renders in-process (local terminal, no
daemon PTY service). Agent drop after stopping 9 of 12: baseline first-third
mean 251.5 MB → last-third mean 157.4 MB (tail mean 87.0 MB); branch
first-third 248.5 MB → last-third 106.1 MB (tail mean 45.2 MB) — the
remainder is the 3 kept agents. GUI stays flat (~190 MB branch, ~163–187 MB
baseline tail).

## How to rerun

```sh
# from the repo root
export CARGO_BUILD_JOBS=4 CARGO_TARGET_DIR=$HOME/.cache/dragent-perf-team-target
# from dragent/: performance-harness build + dev-terminal window is required
# for the automation `run` path the GUI measures use
cargo build -p dragent --features performance-harness
python3 dragent/scripts/bench/gui_app.py --out dragent/docs/perf/data
# headless proxies only:
python3 dragent/scripts/bench/run.py --out dragent/docs/perf/data \
  throughput git-status diff-open worktree-create tab-switch
```

Compare a new run against this file's tables and the CSVs in `data/`
(< 40 KB total). In-app rows need a desktop session to open windows.
